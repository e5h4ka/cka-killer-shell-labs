## Утверждённые решения

1. Один активный вопрос на кластер, а не одновременная установка всего экзамена.
2. Исходные имена ресурсов и /opt/course сохраняются; имена узлов обнаруживаются. Для 1/12 число реплик = workers + 1, строгий вариант на двух workers остаётся отдельным профилем.
3. Для системных задач — отдельная свежая сессия; 1/20 экспериментальная до проверки совместимости, без обещания универсального отката CIDR.
4. Etcd restore из объяснения 2/7 — дополнительное упражнение, не обязательная часть исходного задания.
5. Python standard library + Bash, функциональные проверки и checkpoints для промежуточных действий.

## Git

Последнее конкретное указание пользователя задаёт исключение для текущего этапа: feature/killer-shell-labs от свежей origin/main, только проектная документация, один push. main не изменять и не сливать.

После утверждения реализация ведётся исключительно в dev. Если dev отсутствует — создать от актуальной origin/main, затем перенести утверждённый docs-коммит cherry-pick без merge в main. Коммиты только по завершённым этапам с docs:/feat:/fix:/test:, push один раз после проверок этапа. Существующий write-test.txt унаследован от main, в текущий docs-коммит не входит; его удаление отложено до согласованной реализации.

Обновлять этот план при каждом этапе. Статусы «реализовано», «локально проверено» и «подтверждено в Killercoda» учитывать отдельно; BLOCKED не считать PASS.
